ParcelPe AI Support Desk — Architecture

Every customer message goes through the same 7 steps. Three of them are guardrails that sit around the AI.
👤 Customer
WhatsApp · email · web
text + optional photo
→
frontend/ · React + Vite
port 3000 (nginx in Docker)
Live demo · Ops console · Evals · Database
POST /api/messages
────→
backend/ · Python FastAPI · port 8000
api.py → agent.py (the 7-step loop below)
The agent loop · backend/app/agent.py
1Input guardrail
Mask Aadhaar, PAN, phone, email → [PHONE]…
Catch prompt injection → human
→
2Understand (LLM)
Intent, tracking ID, confidence
→
3Act (tools)
track_parcel · photo_check · check_refund_policy · update_address
→
4Action guardrail
Payout > ₹2,000, repeat claimer or confidence < 70% → human
→
5Draft reply (LLM)
Written only from verified facts
→
6Output guardrail
No unapproved refund promise, no personal data, not too long
→
7Audit trail
Every step, decision, cost and time saved
✨ Google Gemini (steps 2, 3, 5)
Reads the message, checks the photo, writes the reply.
If Gemini is down or the key is wrong → message goes to a human.
🍃 MongoDB (steps 3, 7)
parcels · messages · tickets · refunds
Browse at localhost:8081 (Mongo Express)
🧑‍💼 Human review queue (from steps 1, 4, 6)
Ops console → Approve / Reject.
Approved refunds are saved as “approved by support lead”.
